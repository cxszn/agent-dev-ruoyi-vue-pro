# 芋道模块与代码生成

先区分“使用生成器建立业务功能”和“修改生成器本身”，再读[生成流程与源码入口](references/workflow.md)。确定目标模块、数据库方言、表模型、前端变体和生成范围。

按任务读取参考：

- 从自然语言建模、已有表反向生成或加/改/删字段：继续阅读 workflow 的场景分流与增量流程，再读[字段、API 与产物契约](references/contracts.md)。
- 配置生成器或调用其接口：读[生成器元数据与接口](references/metadata-api.md)，从当前源码确认参数及操作范围。
- 生成或诊断菜单、按钮、角色入口：读[菜单与权限](references/menu-permissions.md)；需要查询或应用系统主数据时使用 [yudao-system](../yudao-system/SKILL.md)。
- UniApp 管理端生成：读[移动端接入与验收](references/mobile.md)，同时核对实际前端工程。
- 需要追溯本次合并、来源版本或许可：读[导入来源与适用性](references/import-provenance.md)。

优先从当前工作区、项目说明和配置获取路径、包名、数据库方言与前端类型；只对会改变业务行为、数据模型、兼容性或操作范围的缺失信息提问。说明必要假设后，沿用用户已有明确授权推进，无需机械要求每一步重复确认。

预览生成文件后再合并。已有业务文件逐项审查差异，生成的 SQL、菜单权限、错误码和前端路由仍需各自验收；生成器成功返回不证明业务可运行。

代码和 SQL 文件的生成，与数据库执行、系统 API 写入和角色授权分别核对授权范围。先查询并复用已有字典、菜单、部门等数据；本地地址不等于写入许可。缺少授权时完成可审查产物并列出待应用项；不为完成代码生成自动创建管理员、给已有用户加 admin、分配角色或关闭验证码。

主子表核对关联字段与保存语义，树表核对父键与展示字段，移动端核对实际 UniApp工程及 WOT组件版本。模板类型与前端类型是两组独立选项。

修改模板时运行相关生成器回归，审查文件集合与语义；不得用重新生成全部断言文件来掩盖失败。模板覆盖范围、配置开关、真实测试证据和未运行项应出现在交付中。
