# 新增方法注释约定

用户约定，更新于 2026-09-23：编写芋道项目及框架代码时，每个新增方法都必须添加注释，说明文字尽可能使用中文，便于开发者查阅和理解。

新增方法的文档注释按本次明确要求执行；“只在逻辑不自明时补注释”的通用建议不用于省略方法说明，方法体内的解释性注释仍按实际需要添加。

## 适用范围

- 覆盖本次新增的显式方法和函数，包括接口声明、实现方法、构造方法、重写方法，以及 public、protected、private 方法和辅助函数。方法简短或名称清楚也需要注释。
- 手写代码和代码生成后交付的源码采用同一要求。修改生成器模板时，检查实际生成的方法是否带有注释。
- 约定针对新增方法；修改已有方法的行为时，同步修正相关注释。历史未改动的方法按原任务范围处理。

## 写法

新增或修改的注释优先使用中文，包括方法用途、参数含义、返回值、异常条件和方法体内的逻辑说明。代码标识符、API 名称、协议名称、必要的英文术语及 `@param`、`@return` 等标签保留原文；确有必须使用英文的接口文档要求时，仅相应部分沿用英文。

注释放在方法声明之前，沿用目标项目的注释格式。Java 优先使用 Javadoc，JavaScript/TypeScript 优先使用 JSDoc/TSDoc；简单方法可以用一句准确的中文说明用途。

至少说明方法做什么。参数的业务含义、单位或取值限制、返回值、异常、事务或其它副作用影响调用者时，一并写明；无关的标签和重复方法名的空话无需堆积。注释必须与实际实现一致，不能写尚未实现的权限、幂等或事务保障。

```java
/** 根据启用标记返回界面显示名称。 */
private String toStatusLabel(boolean enabled) {
    return enabled ? "启用" : "停用";
}
```

类注释、Swagger 的 `@Operation`、`@Override` 等注解不能替代新增方法的注释。方法体内的注释用于解释必要的逻辑和取舍，与方法用途说明配合使用。

## 交付检查

逐一核对本次 diff 中新增的方法/函数及其源码上下文，确认都有用途说明，并检查新增或修改的注释是否优先使用中文、是否与参数、返回值、异常和实际行为相符。必要的英文标识与术语不视为违反语言约定。生成代码还要检查生成产物。缺少注释属于本项目明确约定的未满足项，交付前补齐。
